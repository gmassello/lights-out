# Notes API — small factory test case

## Goal

Build a tiny HTTP service that stores text notes. The product is deliberately trivial: this case
exists to exercise every seat of the factory end to end, not to challenge the implementation.

## Spec

### Runtime contract

- Listen on `0.0.0.0`, port from the `PORT` environment variable (default `8080`). No other
  configuration; no network access at runtime.
- `GET /health` returns `200` with `{"status":"ok"}` within 30 seconds of container start.
- `POST /_test/reset` deletes all notes and idempotency records, and returns `204` with no body
  within 10 seconds.
- Every error response has status 4xx and the body
  `{"error":{"code":"<code>","message":"<human readable>"}}`.
- Any unknown route or method returns `404` with code `not_found`.
- Storage may be in memory.

### Note

```json
{"id": "<opaque string>", "title": "<string>", "body": "<string>", "created_at": "<RFC 3339 UTC>"}
```

- `title`: required, string, 1 to 200 characters after trimming surrounding whitespace.
- `body`: optional string, up to 10,000 characters; defaults to `""`.
- `id`: generated by the server, unique, never reused after a delete or reset.

### Endpoints

| Method and path | Success | Errors |
|---|---|---|
| `POST /notes` | `201` with the created note | `400 bad_request` (body is not a JSON object), `422 validation_error` (invalid `title` or `body`), `409 idempotency_conflict` |
| `GET /notes` | `200` with `{"notes":[...]}` in creation order | — |
| `GET /notes/{id}` | `200` with the note | `404 not_found` |
| `DELETE /notes/{id}` | `204`, no body | `404 not_found` (including a second delete) |

### Idempotent create

- `POST /notes` accepts an optional `Idempotency-Key` header.
- The first request with a given key creates the note and records the response.
- A later request with the same key and the same JSON body returns the recorded response (`201`, same
  note, same `id`) without creating anything.
- A later request with the same key and a different body returns `409 idempotency_conflict` and
  creates nothing.
- Requests without the header always create a new note.
